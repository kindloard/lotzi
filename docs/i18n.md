# Lotzi i18n Architecture

Lotzi uses `next-intl` with always-prefixed locale routes:

- English: `/en/...`
- Tamil: `/ta/...`

The default locale is English. Tamil is the first localized market language. Future locales should be added through `frontend/src/i18n/routing.ts` and `frontend/src/i18n/locale-meta.ts`.

## Namespaces

Translation files live under `frontend/src/locales/{locale}` and are split by product surface:

- `common.json`
- `auth.json`
- `onboarding.json`
- `dashboard.json`
- `marketplace.json`
- `cart.json`
- `admin.json`
- `errors.json`
- `metadata.json`

Do not add a giant shared translation file. Put copy in the namespace that owns the user experience. Shared actions, navigation labels, status labels, and count messages belong in `common`.

## Tamil Glossary

Use these terms consistently:

- Account: கணக்கு
- Store: கடை
- Merchant: வணிகர்
- Order: ஆர்டர்
- Draft: வரைவு
- Approval: ஒப்புதல்
- Dashboard: டாஷ்போர்டு
- Inventory: சரக்கு
- Payout: பணம் பெறுதல்
- Verification: சரிபார்ப்பு
- Customer: வாடிக்கையாளர்
- Product: பொருள்

User-entered content is never translated: product names, customer names, store names, SKUs, emails, addresses, and merchant descriptions stay as provided.

## ICU Rules

All count-sensitive messages must use ICU MessageFormat. English and Tamil both use explicit `=0`, `=1`, and `other` branches so zero and singular copy remains natural.

Use ICU `select` for stable enums such as statuses, payment states, roles, lifecycle states, and upload states. Do not branch on English display labels in code.

## Fallback And Telemetry

Tamil messages are deep-merged over English. Missing Tamil keys render English and emit `lotzi_i18n_fallback_total{locale,namespace,key,route_template}`.

The `route_template` label must be normalized, for example `/[locale]/merchant/products/[productId]`. Never send raw dynamic URLs such as `/ta/merchant/products/abc123`.

Client fallback telemetry is de-duplicated per session before `sendBeacon` sends it to `/api/observability/i18n-fallback`.

Recommended production alerts:

- Warning: any non-English fallback in `auth`, `onboarding`, `errors`, or `metadata` for 15 minutes.
- Critical: `auth` or `onboarding` fallback count is greater than zero after release soak.
- Critical: total fallback count is greater than 25 in 15 minutes.

## Locale Persistence

Locale preferences use:

- Cookie: `lotzi_locale`
- Cookie attributes: `Path=/`, `SameSite=Lax`, `Secure` in production, non-HttpOnly by design because the client language switcher mirrors the value.
- localStorage mirror: `lotzi:locale`

The URL remains the source of truth during SSR.

## Onboarding Locale Switch

Merchant onboarding snapshots current step and values to `sessionStorage` before locale switches. Snapshots include `createdAt`, expire after 30 minutes, and are cleared after successful hydration, step completion, launch, discard flows, logout, or expiry.

## CI

Run:

```bash
npm run i18n:check
```

This checks English/Tamil key parity, duplicate keys, ICU argument parity, and reports hardcoded copy candidates. Use strict mode during migration burn-down:

```bash
npm run i18n:check:strict
```
